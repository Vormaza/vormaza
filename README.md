### `03` &nbsp;How I work

**Tests that run in one command.** A recent project ships with 87 checks that
run against an in-process stand-in for the datastore — no server to start, and
no way for a test run to touch anything real.

**Security in the build, not in a pass afterwards.** Strict CSP, signed
single-use tokens for anything that writes, rate limits per address and a
ceiling over all of them, credentials hashed rather than compared.

**Measured, not assumed.** Before a fix is called a fix I reproduce the
failure and check the claim, including my own. Performance, accessibility and
metadata get audited the same way.

**Commits that explain the why.** The diff already says what changed. The
message is for the person who has to touch it next year.
